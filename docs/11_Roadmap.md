# 11 - Roadmap

## Objectif

La roadmap définit les grandes étapes de développement de Legora.

Elle permet de garder une vision claire des priorités sans figer tous les détails trop tôt.

---

## Phase 1 - Fondation

Objectifs :

- mettre en place le projet ;
- définir le design system ;
- organiser l’architecture ;
- préparer la base de données ;
- mettre en place l’authentification ;
- sécuriser les premières routes.

---

## Phase 2 - Gestion des utilisateurs

Objectifs :

- inscription ;
- connexion ;
- gestion du profil ;
- création d’un cabinet ;
- ajout de membres ;
- gestion des rôles.

---

## Phase 3 - Gestion des clients

Objectifs :

- créer un client ;
- modifier un client ;
- consulter sa fiche ;
- rechercher un client ;
- archiver un client.

---

## Phase 4 - Gestion des dossiers

Objectifs :

- créer un dossier ;
- associer un client ;
- ajouter des notes ;
- suivre le statut ;
- gérer les échéances ;
- archiver un dossier.

---

## Phase 5 - Documents

Objectifs :

- téléverser des documents ;
- classer les fichiers ;
- prévisualiser les pièces ;
- contrôler les permissions ;
- rechercher dans les documents.

---

## Phase 6 - Tâches et calendrier

Objectifs :

- créer des tâches ;
- définir des échéances ;
- assigner des membres ;
- afficher un calendrier ;
- envoyer des rappels.

---

## Phase 7 - Intelligence artificielle

Objectifs :

- résumer des documents ;
- extraire des informations ;
- générer des brouillons ;
- rechercher dans un dossier ;
- ajouter un assistant juridique contrôlé.

---

## Phase 8 - Facturation

Objectifs :

- créer des factures ;
- suivre les paiements ;
- gérer les statuts ;
- exporter les documents ;
- ajouter les abonnements SaaS.

---

## Phase 9 - Notifications

Objectifs :

- notifications dans l’application ;
- rappels par e-mail ;
- alertes d’échéance ;
- notifications d’activité ;
- préférences utilisateur.

---

## Phase 10 - Qualité et production

Objectifs :

- renforcer les tests ;
- améliorer les performances ;
- finaliser la sécurité ;
- mettre en place la surveillance ;
- préparer les sauvegardes ;
- documenter les procédures.

---

## Priorités

Les fonctionnalités sont classées selon trois niveaux :

### Priorité haute

Fonctionnalités indispensables au fonctionnement principal.

### Priorité moyenne

Fonctionnalités importantes mais non bloquantes.

### Priorité basse

Améliorations et options avancées.

---

## Version initiale

La première version utilisable doit au minimum permettre :

- l’authentification ;
- la gestion d’un cabinet ;
- la gestion des clients ;
- la gestion des dossiers ;
- l’ajout de documents ;
- la gestion des tâches ;
- les permissions de base.

---

## Après la première version

Les améliorations pourront inclure :

- l’intelligence artificielle ;
- la facturation ;
- les intégrations externes ;
- la signature électronique ;
- les statistiques ;
- l’application mobile ;
- l’automatisation avancée.

---

## Principe d’évolution

La roadmap pourra évoluer selon :

- les retours utilisateurs ;
- les contraintes techniques ;
- les priorités métier ;
- les coûts ;
- la sécurité ;
- la réglementation.

---

## À préciser plus tard

Cette documentation sera complétée avec :

- les dates ;
- les versions ;
- les priorités détaillées ;
- les dépendances entre fonctionnalités ;
- les critères de validation ;
- les objectifs de mise en production.
